# Contributing

Thanks for looking at Operator Key. This document describes what the project guarantees,
because a contribution that breaks one of those guarantees cannot be merged however good
it looks.

## The invariants

These are not style preferences. Each one is enforced by tests.

1. **The app never executes a command.** It searches, explains, copies, and types text into
   a terminal the operator already has focused. Pressing Enter is always the operator's
   act. There is no execution path, and adding one changes what this product is.

2. **Command text comes from the catalog, never from a model.** A reasoning provider
   returns catalog IDs, which are validated against the exact candidate set that was sent.
   The app then renders the command from its own trusted data. This is what makes a small,
   untrusted, local model safe to use here.

3. **The app ships no credential, no endpoint and no account.** Nothing about the machine
   that built a release may appear in it. If your change makes the app read, store, or log
   authentication material, it will be rejected.

4. **Reasoning talks only to loopback.** Checked after address resolution, not by matching
   on the hostname.

5. **Dangerous commands are copy-only.** Red-classified entries are never inserted.

6. **Nothing machine-specific is committed.** No absolute home paths, no personal email
   addresses, no private network addresses, no generated freshness data. CI enforces this;
   run `bash scripts/ci/check-no-machine-state.sh` before pushing.

## Getting set up

```bash
npm ci
python3 -m unittest discover -s tests   # 160 tests, standard library only
npm test -- --run                       # TypeScript
cd src-tauri && cargo test --lib        # native boundaries
```

For the desktop build you also need the Tauri Linux system dependencies (WebKitGTK, GTK3,
libayatana-appindicator, librsvg).

## Before you open a pull request

Run what CI runs:

```bash
npx tsc --noEmit
npm run lint
npm test -- --run
python3 -m unittest discover -s tests
cd src-tauri && cargo fmt --check && cargo clippy --all-targets -- -D warnings && cargo test --lib
bash scripts/ci/check-no-machine-state.sh
```

## What a good change looks like

**Verify by running, not by asserting.** The most valuable bugs in this repository were
found by executing the real thing and reading the output — a freshness check that reported
a release candidate as an update, lesson text that printed literal backticks at a beginner.
Green structural tests did not catch either. If you change something an operator reads,
read it yourself as that operator.

**Explain why in the commit message.** What broke, how you proved it, what the fix
guarantees. A message that only restates the diff is not useful later.

**Test the failure, not just the success.** A guard that has never been observed rejecting
something is not known to work.

**Catalog changes are data changes.** The catalog is generated by `scripts/build_catalog.py`
from `--help` output on the machine running it. Do not hand-edit `data/catalog.json`.
Safety classification lives in the adapters, and lowering a classification needs a reason.

## Reporting a vulnerability

Do not open a public issue. Follow `SECURITY.md`.
